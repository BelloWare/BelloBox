## Actual Linux interaction

Ran the app on the cloud Linux/X11 desktop with the software Vulkan renderer,
separate Rust settings, `BELLOBOX_TOOL=screenshot` and
`BELLOBOX_INLINE_AREA_FIXTURE=1`. All displayed image pixels were generated by the
app. No ordinary Screen action, permission flow, native acquisition or OCR backend
was used.

The broad candidate passed these observed interactions:

1. Draw a region on the frozen surface. The same overlay acquires its toolbar,
   dim cutout and eight handles; a separate editor window is not opened.
2. Select Rectangle and draw an orange rectangle. The completed preview shows it
   at the expected document location: [inline-annotation.jpg](inline-annotation.jpg).
3. Drag the right handle outward, then press Ctrl+Z once. The cutout returns to
   its prior bounds and the rectangle remains. Select-move changes the crop and
   toolbar location without moving the rectangle's pixels.
4. Open the color panel. It is positioned below the moved toolbar and remains
   within the overlay. Dragging over a covered selection handle does not resize
   the crop; Escape dismisses the panel and preserves the editor/selection.
5. Move focus to the chooser and then the terminal. The locked editor persists.
   Return with a pointer and use the shared Crop tool; the cutout follows it.
6. Return performs Copy & Finish. The overlay disappears and capture-busy clears.
   Paste Image reimports an actual **781×341** PNG with the rectangle baked into
   it, rather than the 2000×1280 full display. The normal popup has no Area handles
   and a clean imported Undo baseline:
   [clipboard-export.jpg](clipboard-export.jpg).
7. Escape closes the imported popup normally.

The final rebuilt candidate was independently rechecked:

- Focus the still-unlocked selector with a blank click, then move focus to the

- Close and relaunch. A fresh region mounts the inline editor with a clean initial

- Return copies/finishes, removes the overlay, clears busy and progress text, and

Screenshots are the original returned JPEG bytes, correctly named `.jpg`; they

## Deliberate limits

The Xfwm window manager skips the notification-style popup in Alt-Tab. Actual
keyboard-only return to that popup is therefore not claimed; the logical GPUI
focus regression is separately tested. Source AppKit activation, key restoration,
Spaces/Stage Manager, native dialogs, accessibility/IME, multi-display/Retina and
hotplug behavior remain native runtime gates. Save dialogs were not accepted by
this QA; only the shared guarded output preparation was validated here.

All handles, mask/crop export interruptions, topological changes and delayed
resource-drain races have GPUI coverage, not an exhaustive manual desktop matrix.
Preview rendering remains asynchronous; these observations are not latency/FPS
measurements. New exact-commit Linux/macOS CI must still be read separately.
Production Area/Window gates remain disabled; this is an integrated supplied-pixel
host checkpoint, not capture enablement or full application parity.
