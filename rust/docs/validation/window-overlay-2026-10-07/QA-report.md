## Actual cloud Linux GUI

The executable ran on the existing cloud Linux/X11 desktop with software Vulkan,
an isolated settings directory, `BELLOBOX_TOOL=screenshot` and
`BELLOBOX_INLINE_WINDOW_FIXTURE=1`. Every image was generated by the app. No
ordinary Screen action, native enumeration, Screen Recording permission, real
screen image acquisition, OCR backend or provider was used.

1. A blank click leaves selection unlocked. A roughly 30-point drag over the
   orange window only updates hover and never opens an Area or editor.
2. Clicking orange mounts the real editor in the same 800×500 overlay. There are
   no resize handles. The selected frame is unchanged; orange frozen pixels and
   rounded transparent corner cutouts remain after alpha refresh:
   [front-alpha.jpg](front-alpha.jpg).
3. Crop a wide strip from the orange body, excluding its contrasting dark header.
   The frame and toolbar stay fixed. The body aspect-fits with clean well-colored
   bands above and below; excluded header/base pixels do not leak into those bands:
   [crop-letterbox.jpg](crop-letterbox.jpg).
4. Begin a text label near the cropped image's lower edge. Its live field extends
   into the lower padding and remains visible and editable. Typing after clicking
   the field shows `edge`: [edge-label.jpg](edge-label.jpg). Escape cancels the draft.
5. Ctrl+Z restores the original dark header without moving the frame/toolbar.
   Ctrl+Shift+Z restores the wide crop and its letterboxes. The draft label is absent.
6. Return performs Copy & Finish, closes the overlay and clears chooser progress/
   busy. Paste Image reimports an actual **401×161** body-only image with clean
   history and no other windows or full-display pixels:
   [cropped-clipboard.jpg](cropped-clipboard.jpg). These are the observed exported
   dimensions. This run did not instrument fractional pointer/layout coordinates;
   exact-coordinate and outward-rounding contracts are separate automated evidence.
7. Close the imported image and relaunch. Click the exposed blue back window.
   Independent blue pixels replace the orange overlap within its selected frame,
   while the separate frozen orange background stays dim outside it:
   [back-independent.jpg](back-independent.jpg).
8. Escape closes the back Window editor, then Escape closes the chooser. The final
   inventory contains no BelloBox window and returns focus to the idle terminal.
   The final runtime output log was empty. Desktop ownership was released.

The initial bound-window automation route did not activate the notification-style
popup; its unlocked focus-loss handling retired it. Those injected bound-window
attempts are not gesture acceptance. The successful matrix above used actual
foreground desktop pointer/keyboard input. Image preparation is asynchronous;
a well-only canvas was observed before the next settled preview. No latency or
frame-presentation claim follows from these captures.

## Remaining gates

This is supplied-pixel host acceptance, not native AppKit/ScreenCaptureKit/TCC,
Spaces/Stage Manager, Retina, multi-display, protected-content or original-color
acceptance. Native normalized SDR masking is covered separately by its existing
strict oracle; exact new-commit native CI must be inspected after publication.
The selector supports the bounded normal-layer, wholly-main-display scope only.
The supplied catalog is at most 512 rows and includes bounded quadratic duplicate
checks; this checkpoint makes no UI latency or performance claim from that bound.

No system Save dialog was accepted in this matrix. Exact capture permissions,
native catalog acquisition, live callback lifetime, accessibility/IME, and complete
source UI fidelity remain separate gates. Production Area/Window capture remains
unavailable. No release, signing, migration of real settings, credentials or paid
service was performed.
