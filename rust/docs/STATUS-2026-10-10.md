## What an ordinary user gets today

A release build (`cargo build --release -p bellobox-app`) opens the source-shaped
Home window and separate tool windows. Working offline: launcher palette with
search/favorites/recents, 51 developer-tool engines (many are subsets of the Swift
tools; dedicated windows for JSON, Compare, Regex, URL, HTTP, Text Tools, QR, World
Clock, Snippets), screenshot editor on imported images, local OCR, and explicit
full-display Screen capture (native-unverified). AI requests use provider settings plus an API key from
the `BELLOBOX_AI_KEY` environment variable only. The app uses a separate preview
identity (`com.ainoob.BelloBox.rust.preview`) and its own settings/snippet files.

Production gates that are **closed** in source: Area capture, Window capture,
recording, native movie reading (so no movie→GIF conversion), AI OCR upload
(`PRODUCTION_*`/`NATIVE_*_IMPLEMENTED = false`).

## Parity defects found on 2026-10-10

1. **JSON value limit (fixed in this checkpoint).** Rust rejected documents over
   20,000 values that `DeveloperJSON.swift` formats (it bounds only input bytes and
   depth 64). The formatter's value counter is removed; depth errors now use
   Swift's message and position.
2. **Sort A→Z and Trim (fixed in this checkpoint).** Swift `LineTool` sorts with
   `localizedCaseInsensitiveCompare` and trims `CharacterSet.whitespaces`; Rust
   sorted by bytes and trimmed Unicode `White_Space`. macOS now sorts through the
   same Foundation call (byte-identical to Swift on the 490 KB fixture, 47 vs
   221 ms); Trim/Remove empty use Swift's set, now asserted by the native oracle.
3. **Input cap (open, minor).** Swift `UtilityLimits.inputBytes` is 512,000 bytes;
   Rust tools cap at 500,000 bytes including the option field. The limits and
   messages differ per tool (Swift JSON allows 512,000 bytes and says "Use up to
   500 KB of text at a time."), so this needs a per-tool pass, not one constant.
4. **Local OCR layout (fixed in this checkpoint).** Its first macOS run showed
   Rust returned Vision's lines in Vision's order with no paragraph breaks,
   recognized nothing on an 8000 px tall page (Swift reads it in overlapping
   bands) and reported an empty result as success. Rust now ports Swift's
   bands, reading order, de-duplication and formatter; output is byte-identical
   to the Swift oracle on all six generated images.

## Release blockers

1. Settings/Keychain/snippets migration with backup and rollback, preserving the
   production identity `com.ainoob.BelloBox` and Sparkle trust.
2. The capture product: Area/Window/scrolling capture and recording are closed;
   GIF from movies needs the native movie reader.
3. Selection capture, global hotkeys, floating toolbar, menu bar, onboarding.
4. macOS interactive acceptance (focus, IME, VoiceOver, permissions/TCC).
5. Signed/notarized packaging and a Rust update feed.

(CI, red at takeover, is green on Linux and macOS since `6a20b2b`.)

A Rust replacement for the next release is not realistic; the capture and
selection workflows that define the product are the largest gaps.
